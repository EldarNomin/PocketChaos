# Дворовые пенальти · прототип 0.6

Этап 5 (в работе): сетевая дуэль на двоих со щитами и вентиляторами — настройки, обучение, звук и оформленный двор в единой палитре. Один бьёт, второй защищает ворота, затем роли меняются. Графика стилизованная, из простых фигур.

## Запуск на Windows

1. Распакуйте готовую Windows-сборку и запустите `StartGame.bat`. Движок уже включён.
2. Если скачали ZIP репозитория через **Code → Download ZIP**, откройте `games/penalty-yard` и запустите `StartGame.bat`.

Для исходников при первом запуске нужен интернет: скрипт скачивает официальный Godot 4.5.1 (около 73 МБ), проверяет SHA-512 и сохраняет движок в `.engine`. Установка редактора и права администратора не нужны. Следующие запуски работают без загрузки движка.

На Windows/Linux/macOS можно открыть `project.godot` в Godot **4.5.1 Standard** и нажать F5. Версия .NET не требуется.

## Как сыграть вдвоём

1. Оба запускают одинаковую версию игры и нажимают **Онлайн**.
2. Хозяин нажимает **Создать**. Порт по умолчанию — **24567**.
3. Друг вводит IP хозяина, тот же порт и нажимает **Подключиться**. Последний удачный адрес и порт подставляются при следующем запуске.
4. Оба нажимают **Готов** или **R**. После отсчёта у бьющего 10 секунд на удар.
5. После результата роли автоматически меняются. Перед следующей попыткой снова нужна готовность обоих.

Для проверки на одном ПК запустите два окна: адрес `127.0.0.1`. На двух ПК в одной локальной сети используйте локальный IP хозяина, показанный при создании комнаты.

Между разными сетями хозяин должен быть доступен по введённому IP и **UDP-порту 24567** (или выбранному другому порту). При NAT может потребоваться проброс UDP-порта на роутере; при CGNAT прямое соединение может быть недоступно. Разрешите доступ игре в брандмауэре, если Windows покажет запрос. Steam Relay, приглашения друзей и подбор соперника ещё не подключены. Тесты выполнены на localhost, соединение между реальными удалёнными сетями пока не проверено.

## Правила матча

- Пять раундов: в каждом оба игрока выполняют по одному удару.
- Первого бьющего выбираем случайно; в следующем раунде первым начинает другой игрок.
- Гол даёт одно очко. Ловля, промах или истечение времени не дают очков.
- Победитель определяется после обеих попыток последнего раунда.
- При равенстве — дополнительные парные раунды: максимум пять, затем ничья.
- Реванш запускается только по согласию обоих. Счёт сбрасывается, начальный игрок меняется.
- При отключении матч прерывается. Можно создать новую комнату; переподключения к прежнему матчу пока нет.
- Меню Esc не останавливает сетевой матч. В локальной тренировке это настоящая пауза.

Мяч, ловлю и счёт рассчитывает компьютер хозяина. Второй игрок отправляет управление и получает состояние; результат гола не вычисляется отдельно на двух ПК. Визуальное сглаживание и предсказание движения вратаря помогают управлению, но ощущение ловли при высоком пинге ещё требует проверки людьми.

## Предметы и строительство

Первый раунд проходит на пустом поле. Перед раундами 2–5 каждый получает один ход по 15 секунд: щит, вентилятор влево или вправо, либо пропуск. Порядок первого строителя чередуется.

Выбери карточку слева и кликни по ячейке площадки. Щит можно повернуть Q/E. У каждого два места: выбери нужное кнопкой или клавишей 1/2, чтобы заменить свой предмет. Всего на поле до четырёх предметов. Предметы соперника менять нельзя; недопустимое размещение подсвечивается красным и объясняется. R пропускает ход.

Щит отражает мяч. Вентилятор отклоняет его в видимой зоне 2 × 2 м до высоты 2,5 м; стрелки показывают направление. Цвет предмета обозначает владельца. Оба удара раунда проходят на одинаковом поле; дополнительные попытки также идут без нового строительства. На реванше поле очищается.

Для пробы без второго игрока нажми **Поле / B** в тренировке, поставь предмет и выполни удар. Можно добавить второй предмет или заменить прежний. **Пустое поле** очищает тренировочную площадку.

## Настройки, обучение и звук

При первом запуске показывается короткое обучение из пяти страниц: матч, бьющий, вратарь, площадка и онлайн. Повторно его можно открыть из **Настроек** или меню паузы.

В **Настройках** регулируется громкость (применяется сразу) и переключается полноэкранный режим; оба значения сохраняются между запусками. Esc закрывает настройки и обучение; в онлайне матч при этом продолжает идти.

Звуки синтезируются без внешних файлов: удар, свисток перед попыткой, касание мяча, ловля, гол, спасение, промах и установка предмета. Оба игрока слышат одинаковые события.

## Управление

| Клавиша | Действие |
|---|---|
| R | Онлайн: готовность / согласие на реванш; тренировка: повтор попытки |
| Esc | Открыть / закрыть меню |
| Мышь | Направление удара или положение рук |
| ЛКМ, удержать и отпустить | Зарядить силу и ударить |
| ПКМ | Отменить подготовку удара |
| Q / E | Убавить / прибавить подкрутку |
| ЛКМ у вратаря | Короткое окно ловли, когда мяч рядом с руками |
| A / D | Двигаться вдоль ворот |
| Space + A / D | Один рывок на попытку |
| 1 / 2 | Тренировка: роль; строительство: своё место |
| B | Открыть / закрыть поле в тренировке |

Подкрутка и отскоки меняют итоговую точку попадания. Постоянное удержание кнопки не продлевает ловлю. Движение A/D соответствует направлению на экране.

Локальные режимы сохранены: удар по пустым воротам и пять повторяющихся типов тренировочных ударов для вратаря.

## Что проверить Эльдару

1. Подключение и одинаковый счёт после нескольких ударов.
2. Удобно ли ловить настоящего соперника и читать направление мяча?
3. Есть ли преимущество хозяина по ощущению задержки?
4. Понятны ли готовность, смена ролей и реванш?
5. Хочется ли сыграть второй матч без наград?
6. Понятно ли обучение при первом запуске и не мешает ли оно вернуться в игру?
7. Различимы ли звуки удара, ловли, гола и установки предмета при общей громкости?

Сборка Windows требует пользовательской проверки; автоматические проверки выполнены в Linux/Godot. Увлекательность и баланс пока не подтверждены игроками.

## Разработка и проверки

Настройки: `scripts/tuning.gd`. Правила гола и ловли: `scripts/rules.gd`. Матч: `scripts/match_rules.gd`. Сетевая комната и синхронизация: `scripts/session.gd`. Сцена и тренировка: `scripts/game.gd`. Сохраняемые настройки: `scripts/settings.gd`. Звук: `scripts/audio.gd`. Палитра двора: `scripts/style.gd`. Обучение: `scripts/tutorial.gd`.

Рендеры для проверки оформления (запуск без `--headless`, файлы в `.shots/`):

```sh
godot --path . --script tests/render_snapshot.gd
```

Из папки игры, с Godot в PATH:

```sh
godot --headless --editor --import
godot --headless --script tests/test_rules.gd
godot --headless --script tests/test_game.gd
godot --headless --script tests/test_match.gd
godot --headless --script tests/test_settings.gd
godot --headless --script tests/test_network.gd
godot --headless --script tests/test_network.gd -- --latency
godot --headless --script tests/test_field.gd
godot --headless --script tests/test_network_build.gd
godot --headless --script tests/test_network_build.gd -- --latency
```

Из корня репозитория: `python3 tools/test_network_processes.py godot`. Проверка запускает два независимых процесса с настоящей сценой игры и доводит матч до ничьей. Вывод обоих процессов читается непрерывно: ожидание piped-процесса без чтения может остановить его на Windows.

Сетевые тесты используют реальные ENet-соединения: гол, ловля, смена ролей, одинаковый счёт, полный матч, реванш, устаревшие команды, повторный удар и отключение. В варианте `--latency` искусственно добавляем 120 мс к доставке состояний клиенту и его команд хозяину. Пакеты положения рук этим тестом не задерживаются; это не полная симуляция плохого интернет-соединения.

Godot иногда возвращает код 0 при ошибке импорта: также проверяйте вывод на `SCRIPT ERROR` и `ERROR`. В CI это проверяется автоматически.
