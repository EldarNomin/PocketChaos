# Сдача задачи и проверка Codex

## Отчёт GLM

Создай `docs/reports/CM-XXX-implementation.md`. Используй следующий формат в файле и PR:

```md
# CM-XXX — сдача
Задача / граница:
Ветка / PR:
Код проверен на SHA: (SHA реализации, до коммита отчёта; указать любые последующие изменения кода)
Движок / ОС:

## Что изменено
Короткое описание и соответствующие CM-RXX.

## Проверки
| Проверка / точная команда | PASS / FAIL / NOT_RUN | Доказательство |
|---|---|---|
| Import | | |
| Headless smoke | | |
| Тест правил текущей задачи | | |
| Запуск с изображением/мышью | | |
| Windows build (если требуется этапом) | | |

## Демонстрация
Видео реального запуска / скриншоты / CI artifacts.

## Ограничения и оставшиеся риски
Что не проверено, почему, минимальный следующий шаг.
```

Большие видео, ZIP и логи — CI/PR artifacts или внешняя ссылка, не git. Ссылки должны открываться проверяющему. Не помечать весь этап проверенным по одному screenshot.

## Проверка Codex

1. Получить актуальный main, metadata PR, полный diff и head SHA; найти текущую задачу, проверить границы и инструкции.
2. Проверить правила сбора/начисления, UI и паузу, delta/time, лимит спавна, экономику/сохранения, если они уже входят в этап. Отдельно проверить, что заглушки не скрывают отсутствующий функционал.
3. Проверить результаты CI именно для head SHA и самостоятельно выполнить доступные команды. Не приписывать чужие запуски себе. Если редактор/платформа недоступны — использовать прикреплённые доказательства, явно указать предел проверки.
4. Сопоставить каждый критерий текущего этапа с доказательством. Замечание содержит файл/место, сценарий, ожидаемое/фактическое, важность и минимальный ремонт.
5. Решение по этапу: ACCEPTED при выполненных обязательных критериях; CHANGES_REQUESTED при дефектах; BLOCKED при недостаточном доступе/доказательствах. Непроверенную обязательную вещь не считать успешной.
6. Зафиксировать отчёт `docs/reports/CM-XXX-review.md`: PR, SHA, выполненные/чужие/невыполненные проверки, решение, замечания, следующая задача. Обновить STATUS. После новых коммитов перепроверить затронутую область.

Слияние PR допустимо после приёмки в рамках дальнейшего поручения на реализацию/управление проектом. Блокирующие ошибки, невоспроизводимый запуск и потеря прогресса не переносить на следующий этап. Ощущение от игры проверяется реальным запуском и игроками, а не только кодом.
